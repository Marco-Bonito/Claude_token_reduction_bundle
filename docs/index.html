Claude Code plugin · MIT

token-routing

Each task goes to the cheapest model and effort that can do it. The result is checked. Retries escalate only on failure. The table learns from every run.

Script routing
A table and a script pick the model and effort. No model tokens go into the decision.
Small main context
Each micro-task runs in its own subagent. Only a one-line status comes back.
Smart retries
The failure type decides: more effort, a stronger model, an environment fix, or a question to you.
Self-improving
Metrics after every batch. The improver tunes the table and writes lessons, with guardrails.

1. How a run works

flowchart TD
  A[Request] --> B[Draft plan]
  B --> C[Ask max 4 questions]
  C --> D[Plan v2 + digest]
  D --> E[High-level tasks]
  E --> F[decompose: micro-tasks + category + tier]
  F --> G[route.py: model + effort]
  G --> H[route-map.md]
  H --> I[worker]
  I -->|goal met| J[reviewer]
  I -->|goal not met| K[route.py escalate]
  J -->|PASS| L[done]
  J -->|FAIL| K
  K -->|stronger route + failure log| I
  K -->|spec unclear| C
  K -->|blocked| M[report]
  L --> N[metrics + improver]

3. Retries

flowchart LR
  F[Attempt failed] --> T{failure type}
  T -->|depth / review| E[same model, more effort]
  T -->|capability| M[next model]
  T -->|environment| S[fix env, same route once]
  T -->|spec| U[ask the user]
  E --> C{attempt 3 done or ceiling?}
  M --> C
  C -->|no| R[retry with log]
  C -->|yes| B[blocked, report]

4. The improver loop

flowchart LR
  A[Batch ends] --> B[collect: free]
  B --> C{every 3 batches or end}
  C --> D[report: stats per cell]
  D --> E[improver agent]
  E --> F[lessons.md]
  E --> G[prompt / rubric proposals]
  E --> H[veto bad changes]
  H --> I[apply: new table version]
  I -.->|next tasks| J[better routes]
  • First pass below 60% → one ladder step up. Above 95% over 8+ tasks → one step down.
  • After a change, the cell counts only new data.
  • Every change is versioned. Undo with metrics.py rollback.

5. Install

Plugin 
/plugin marketplace add Marco-Bonito/Claude_token_reduction_bundle
/plugin install token-routing@token-routing
Manual 
git clone https://github.com/Marco-Bonito/Claude_token_reduction_bundle.git
scripts/install.sh /path/to/project          # Windows: scripts\install.ps1
Then paste plugins/token-routing/CLAUDE.routing.md into your CLAUDE.md, and do not set CLAUDE_CODE_EFFORT_LEVEL or CLAUDE_CODE_SUBAGENT_MODEL.

6. Use

  1. Type /orchestrate <request>. One goal per run.
  2. Answer the questions. Each one has a recommended option.
  3. Check the route map and cost profile. Correct a tier if it looks wrong. Say "go".
  4. Follow .claude/runs/<run>/route-map.md if you want.
  5. Read the improver summary at the end. Approve or reject the proposals.
  6. Commit .claude/routing/history/. It is what your project learned.

Also: /decompose <task> for only the breakdown, /improve to run the cycle now.
